# Full-Slide Imagegen PPT Workflow

Use this for image-based PPTs where each page is a complete generated slide image.

## Hard Gate

The slide image must come from imagegen. Do not use scripts to directly render final PPT content pages.

Allowed script roles:

- build source manifests and prompt packs
- check imagegen backend readiness
- run or queue per-slide imagegen calls
- copy imagegen outputs into `assets/slides/`
- assemble existing full-slide images into PPTX
- validate and audit outputs

Forbidden script roles:

- drawing full slide pages with PIL, SVG, HTML, Canvas, matplotlib, screenshots, or PowerPoint shapes
- creating local text overlays on generated backgrounds
- creating placeholder or diagnostic pages and treating them as final PPT output
- exporting a script-built editable deck to images and calling that imagegen output

If imagegen cannot run, leave the prompt pack and deck spec ready, report the blocker, and do not claim PPT generation is complete.

## Workflow

1. Check the ImageGen backend before committing to a batch route.
2. Extract source facts and deck intent.
3. Decide page count, audience, language, and one profile from
   `style-system.md`; record whether minimalism is intentional.
4. Write a slide outline with stable slide IDs and varied page archetypes.
5. Write slide scripts: exact title, short on-slide text, message, evidence refs, and visual intent.
6. Write a style contract: palette, typography behavior, motif, density,
   design-completion target, chart/diagram vocabulary, dual quality guardrails,
   and no-reuse constraints.
7. Write one self-contained ImageGen prompt per slide.
8. Generate each slide image with ImageGen.
9. QA images for source fit, text readability, no placeholders, no unsupported facts, and style consistency.
10. Regenerate only failed slides unless the style contract is wrong.
11. Assemble final images into PPTX.
12. Run the ImageGen-first provenance and PPTX-structure gate.
13. Start semantic editable reconstruction only after the gate passes.

## Prompt Requirements

Each slide prompt must stand alone. Include:

- canvas ratio and target resolution
- slide purpose and audience
- exact on-slide text
- evidence anchors or source boundaries
- visual layout blueprint
- style contract summary
- design density and `intentional_minimal`
- design-completion requirements and spectacle/under-design guardrails
- typography/readability instructions
- negative constraints
- acceptance criteria
- regeneration hint

Keep Chinese slide text short and explicit. Use larger typography and fewer
labels rather than paragraphs. If the model produces unreadable Chinese,
shorten the copy and regenerate the whole slide image, but preserve the selected
profile's primary evidence anchor and design finish. Do not solve a text defect
by collapsing a non-minimal slide into a bare template.

## Output Policy

The generated image is the final PPT page:

- must be generated by imagegen
- no local text overlay
- no placeholder background
- no blank template page
- no native chart or shape overlay in PPTX
- no old slide reuse

The PPTX assembly step only places each image full bleed on a blank 16:9 slide.

## Minimal `deck-spec.json`

```json
{
  "deck": {
    "output_mode": "imagegen_full_slide",
    "generation_mode": "direct_final_slide_imagegen"
  },
  "slides": [
    {
      "slide_id": "S01",
      "layout": "full_slide_image",
      "slide_image": "assets/slides/S01.png"
    }
  ]
}
```

## Assembly

```powershell
python autopptskills\scripts\build_competition_ppt.py <deck-spec.json> --output <out.pptx> --report <build-report.json>
```

If the builder reports missing images, generate or copy the missing `assets/slides/Sxx.png` files first. Do not create diagnostic placeholder pages as a substitute for final slides.

The builder does not prove where an image came from. Immediately run:

```powershell
python autopptskills\scripts\verify_imagegen_first_gate.py <run-dir> --pptx <out.pptx> --report <run-dir>\qa\imagegen-first-gate-report.json
```

Use `--require-strong-ig-id` for built-in ImageGen runs. A pass requires one complete-page prompt contract and matching ImageGen provenance per current slide hash, plus exactly one full-slide picture and zero script-added text/native shapes per PPT slide.

## Style Guidance

Default to clear, judge-facing, premium information design:

- one strong message per slide
- a conclusion-led title when possible
- polished `academic_light` styling by default, or another stable profile from
  `style-system.md` when the audience and evidence justify it
- `academic_minimal` is an explicit option, not a rule imposed on every deck
- enough content to justify the slide
- for every non-minimal profile, one content-specific primary evidence anchor,
  clear reading path, deliberate scale contrast, domain-specific visual
  vocabulary, and enough secondary detail to feel complete
- page structures should vary across the deck; do not default every slide to a card grid
- unified palette and typography across the deck
- evidence and product/system visuals should be legible from a projector
- no fake logos, fake awards, fake screenshots, fake customers, or invented metrics

Public NSFC, graduate-defense, discipline-competition, and official university
examples may be studied for composition patterns, hierarchy, page rhythm, and
evidence treatment. Do not copy protected templates, logos, branding, project
claims, or source-specific content.

The image QA ledger must reject both directions:

- `spectacle-control`: fail non-evidence cinematic effects, decorative
  backgrounds, marketing-poster composition, neon/HUD treatment, or visuals
  that compete with the conclusion;
- `design-completion`: fail generic title-plus-bullets, empty card scaffolds,
  timid scale, disconnected icons, accidental whitespace, or a non-minimal page
  without a primary evidence anchor.

When a page fails, regenerate only that page unless the deck-wide style contract
is wrong.
