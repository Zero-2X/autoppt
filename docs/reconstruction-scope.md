# Editable reconstruction scope

The editable reconstruction layer consumes the verified ImageGen output of
the presentation workflow. Its integration boundary is:

```text
Existing presentation workflow (unchanged)
source understanding -> storyline -> slide content spec -> design system -> storyboard
-> Codex built-in image_gen full-slide master -> image QA -> image-only PPTX

Added post-generation layer
-> visual parsing -> component manifest -> object router
-> native text / native shape / SVG group / bounded raster
-> PowerPoint render -> diff / text / semantic QA -> final PPTX
```

## Must remain unchanged

- Source parsing, factual/numeric truth, and narrative structure.
- Existing page design constraints, style profiles, full-slide ImageGen prompts,
  and image-only PPTX assembly.
- Existing PowerPoint rendering, overflow, text, visual, and deck-level QA gates.
- The ImageGen platform boundary: every slide is generated by Codex built-in
  `image_gen`; the repository only receives, verifies, and records the result.

## Allowed additions

- `component_manifest.json` with `content_id`, bbox, z-order, routing,
  confidence, and provenance.
- Mapping reviewed Slide Manifest text to native text boxes.
- Mapping simple geometry to native shapes/connectors.
- Keeping complex illustrations as independent SVG groups or bounded raster
  assets.
- Running the existing Render -> Diff -> Repair and structural/text/semantic
  audits on the reconstructed result.

## Hard prohibitions

- Do not use OCR to rewrite Slide Manifest prose, technical terms, numbers, or formulas.
- Do not ship a full-page `full.svg` or screenshot as the final editable PPT.
- Do not use an API key, provider SDK, proxy, ComfyUI, Stable Diffusion, local
  generation command, or mock image as a substitute for built-in `image_gen`.
- Do not rewrite the existing pre-ImageGen content-understanding or design workflow.
